# EB Recorder

[English version](README.md)

**Windows 10/11 • плагин OBS Studio • Twitch Enhanced Broadcasting**

**EB Recorder** локально записывает активный поток Twitch Enhanced Broadcasting с максимальным разрешением, переиспользуя кодировщик, который OBS уже создал для трансляции.

Главная задача плагина состоит в том, чтобы сохранить качественный локальный VOD **без запуска ещё одного видеокодирования**.

## Зачем это нужно

Enhanced Broadcasting может одновременно создавать несколько видеопотоков для Twitch. Обычная локальная запись при этом способна добавить ещё одну сессию кодирования и дополнительную нагрузку на GPU.

EB Recorder находит уже активные EB-кодировщики OBS, выбирает поток с максимальным разрешением и подключает к отдельному локальному Matroska output существующий видеокодировщик вместе с существующим EB-аудиокодировщиком.

```text
Существующий TOP EB video encoder ─┐
Существующий EB Live AAC encoder ──┼─ EB Recorder -> MKV
Существующий EB VOD AAC encoder  ──┘   (опционально / выбирается)
```

Новый видеокодировщик EB Recorder не создаёт.

## Возможности

- Запись только активного EB-потока с максимальным разрешением.
- Переиспользование существующего EB video encoder без второго видеокодирования.
- Выбор аудио из существующих EB-кодировщиков: **Live**, **VOD** или **Live + VOD**.
- Варианты с VOD недоступны, если текущие настройки вывода OBS не могут создать отдельную дорожку Twitch VOD; ранее сохранённый недоступный выбор автоматически возвращается на Live.
- Переиспользование этих аудиокодировщиков без дополнительного аудиокодирования.
- Запись в Matroska (`.mkv`) в текущую папку записи OBS.
- После штатной остановки добавляются технические Matroska-теги `BPS` для аудиодорожек, чтобы совместимые просмотрщики метаданных могли показывать их битрейт.
- Устойчивость к аварийному завершению за счёт коротких Matroska-кластеров (`cluster_time_limit=1000`).
- Опциональный **автоматический старт записи вместе с EB-трансляцией**.
- Автоматическая остановка локальной записи до уничтожения EB encoder pipeline.
- Ручные Start / Stop остаются доступными.
- Русский и английский интерфейс.
- Плагин не меняет режим дисплея Windows, частоту обновления, VRR, G-SYNC, настройки NVIDIA, реестр, службы, планы питания или PATH.

## Проверенная конфигурация

Текущая версия протестирована с:

- OBS Studio `32.2.2` x64 на Windows
- Twitch Enhanced Broadcasting / Multitrack Video
- NVIDIA NVENC
- TOP-поток: HEVC `2560x1440 60 fps`, около `9000 кбит/с`
- AAC stereo `48 kHz`, `160 кбит/с`

Другие комбинации EB-кодировщиков потенциально могут работать, но пока не входят в проверенную матрицу.

## Установка

1. Откройте раздел **Releases** репозитория.
2. Скачайте последний `EBRecorder-vX.Y.Z-Windows-x64.zip`.
3. Полностью закройте OBS.
4. Распакуйте архив.
5. Запустите `INSTALL.cmd`.
6. Запустите OBS и откройте **Сервис -> EB Recorder**.

Плагин устанавливается изолированно в:

```text
C:\ProgramData\obs-studio\plugins\eb-recorder\
```

Установщик не зависит от папки, в которой установлен OBS, поэтому обычную или Steam-версию OBS можно держать на любом диске.

Установщик не создаёт записей в реестре, служб, задач планировщика и не меняет PATH.

Для удаления закройте OBS и запустите `UNINSTALL.cmd` из распакованного release-архива.

### Установка в portable OBS

`INSTALL.cmd` рассчитан на обычную и Steam-установку OBS. Если OBS работает в portable-режиме, EB Recorder нужно установить вручную в папку portable OBS.

Из распакованного архива EB Recorder:

1. Скопируйте `eb-recorder\bin\64bit\eb-recorder.dll` сюда:

```text
<OBS Portable>\obs-plugins\64bit\eb-recorder.dll
```

2. Создайте эту папку, если её ещё нет:

```text
<OBS Portable>\data\obs-plugins\eb-recorder\locale\
```

3. Скопируйте `en-US.ini` и `ru-RU.ini` из `eb-recorder\data\locale\` в эту папку `locale`.
4. Запустите portable OBS и откройте **Сервис -> EB Recorder**.

Итоговая структура должна выглядеть так:

```text
<OBS Portable>\
├─ bin\64bit\obs64.exe
├─ obs-plugins\64bit\eb-recorder.dll
└─ data\obs-plugins\eb-recorder\locale\
   ├─ en-US.ini
   └─ ru-RU.ini
```

Для portable-установки удаление тоже выполняется вручную. Закройте OBS, удалите `eb-recorder.dll` и папку `data\obs-plugins\eb-recorder`.

## Использование

Сначала запустите Twitch Enhanced Broadcasting. Когда EB-кодировщики OBS станут активными, откройте **Сервис -> EB Recorder**.

Диагностическая таблица показывает найденные EB video encoders. Активный кодировщик с максимальным разрешением помечается как **ВЕРХНИЙ / TOP**.

Нажмите **Начать запись** для ручного старта или включите настройку:

> **Автоматически начинать запись при запуске EB-трансляции**

В автоматическом режиме EB Recorder ждёт появления активных EB video/audio encoder'ов и сам запускает локальную запись. Окно плагина можно держать закрытым.

Снятие галки не останавливает уже идущую запись. Если вы вручную остановите автоматически начатую запись, плагин не запустит её снова в рамках той же трансляции.

## Выходной файл

Файлы сохраняются в ту же папку, которая настроена в OBS для локальной записи. В режиме вывода **Простой** это путь из **Настройки → Вывод → Запись → Путь записи**. Отдельной настройки папки сохранения у EB Recorder нет.

```text
EBRecorder_yyyy-MM-dd_HH-mm-ss.mkv
```

В файл попадает выбранный TOP EB video rendition и выбранное в **Сервис → EB Recorder** аудио: **Live**, **VOD** или **Live + VOD**.

После штатной остановки EB Recorder добавляет для записанных аудиодорожек технические Matroska-теги `BPS`, чтобы совместимые просмотрщики метаданных, включая проверенный Windows Explorer, могли показывать настроенный битрейт AAC. Это небольшая финализация метаданных без remux и повторного кодирования; при аварийном завершении OBS этот необязательный шаг может не выполниться, но приоритет остаётся за воспроизводимостью crash-resilient MKV.

## Устойчивость к аварийному завершению

EB Recorder использует штатный FFmpeg muxer OBS, Matroska и настройку:

```text
cluster_time_limit=1000
```

В тесте MKV остался полностью воспроизводимым после принудительного завершения процесса OBS во время записи. При реальном BSOD или отключении питания небольшой хвост всё равно может потеряться из-за кэшей ОС/накопителя, но уже записанная часть не зависит от штатной финализации файла.

## Производительность

EB Recorder не создаёт новый video encoder. Локальный output получает уже готовые encoded packets от существующего Enhanced Broadcasting encoder и только мультиплексирует их в файл.

В проверенной EB-сессии с тремя rendition'ами OBS по-прежнему показывал три GPU encode thread. Четвёртый поток кодирования из-за EB Recorder не появлялся.

## VRR / G-SYNC

EB Recorder не вызывает Windows display configuration API, DXGI presentation/swap-chain API, NVIDIA NvAPI, API изменения реестра, DWM-настроек, timer resolution или планов питания.

Диагностическое окно опрашивает состояние encoder'ов раз в секунду через coarse Qt timer и перерисовывается только при реальном изменении отображаемого состояния. При закрытом окне и уже запущенной автоматической записи периодического UI repaint loop у EB Recorder нет.

Само видимое окно OBS/Qt всё равно участвует в обычной композиции рабочего стола Windows, поэтому на системах с windowed VRR/G-SYNC специфическое мерцание compositor'а теоретически возможно и не означает, что плагин изменил постоянную настройку дисплея.

## Текущие ограничения

- Проверена только Windows x64.
- Сейчас записывается только активный EB-поток с максимальным разрешением; ручного выбора rendition пока нет.
- Поиск EB encoder'ов опирается на текущую схему имён Multitrack Video в OBS.
- Версия проверена с OBS Studio 32.2.2; будущие изменения OBS могут потребовать обновления совместимости.
- Выбор аудио ограничен существующими EB Live/VOD encoder'ами; произвольные локальные аудиодорожки OBS пока не поддерживаются.
- Если отдельная Twitch VOD-дорожка отключена или не может быть создана текущими настройками OBS, варианты `VOD` и `Live + VOD` в плагине недоступны.
- Отображение битрейта каждой аудиодорожки зависит от поддержки Matroska-тегов `BPS` конкретным просмотрщиком метаданных.
